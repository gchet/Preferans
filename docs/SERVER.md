# Собственный сервер
Проект не предоставляет публичный сервер. Установите на своём VPS две службы:
сигналинг (комнаты, согласование подключений) и coturn (ретрансляция WebRTC).
Пароли TURN и администратора различны. Пароль SSH — отдельный механизм доступа.

## Сборка и запуск сигналинга
~~~powershell
pwsh ./scripts/Update-Signaling.ps1
pwsh ./scripts/Update-Signaling.ps1 -Deploy -Server user@signaling.example.org
~~~
Первая команда только собирает dist/preferans-signaling. Вторая устанавливает
его на указанный VPS; существующие данные, конфиги и TURN не меняются.
Деплой выполняйте только на свой сервер.

Рекомендуемые параметры systemd:
~~~ini
[Unit]
Description=Preferans signaling
After=network-online.target
[Service]
User=preferans
Group=preferans
ExecStart=/usr/local/bin/preferans-signaling -listen :8080 -data /var/lib/preferans-signaling
Restart=on-failure
StateDirectory=preferans-signaling
UMask=0077
[Install]
WantedBy=multi-user.target
~~~
Создайте системного пользователя preferans и файл
/etc/systemd/system/preferans-signaling.service; затем daemon-reload и enable --now.
Перед установкой проверьте параметры через бинарник -help.
Публичный URL комнат имеет вид https://signaling.example.org/v2/rooms
(или HTTP :8080 для доверенного тестового окружения). Настройте HTTPS сертификат
с параметрами -tls-cert и -tls-key. Подробнее об ограничениях: [SECURITY](../SECURITY.md).

## TURN
Конфиг coturn обычно находится в /etc/turnserver.conf; служба coturn.
Минимальная схема (значения замените своими):
~~~ini
listening-port=3478
fingerprint
lt-cred-mech
realm=signaling.example.org
user=preferans:CHANGE_THIS_PASSWORD
min-port=49160
max-port=49200
no-cli
no-multicast-peers
~~~
При внешнем NAT VPS добавьте external-ip=PUBLIC_IP/PRIVATE_IP.
Конфиг с паролем должен быть доступен только root и службе turnserver:
в типичной установке root:turnserver, chmod 640.
Разрешите 3478 UDP/TCP и диапазон relay-портов UDP в firewall ОС и провайдера.
Для TLS настройте сертификат/ключ coturn и 5349 TCP, либо другой выбранный порт.
Никакие пароли не коммитьте.

В приложении задайте сервер комнат, TURN URL
turn:signaling.example.org:3478?transport=udp, имя и пароль.
Для проверки TURN с другого устройства используйте turnutils_uclient из coturn:
~~~sh
turnutils_uclient -u preferans -w YOUR_PASSWORD -p 3478 -y signaling.example.org
~~~
Этот тест подтверждает ретрансляцию между клиентами, а не только доступность порта.
Проверьте также приложение на разных сетях (Wi-Fi и мобильная связь).


## Администратор

Админка — отдельная веб-страница сигналинг-сервера по пути `/admin/`. В игровом приложении вкладки администратора нет.

Первоначальный пароль: **admin**. Раздел **Сменить пароль** требует текущий пароль, новый пароль и его повтор. Новый пароль — от 8 до 72 байт. Проверка происходит на сервере. Пароль хранится только как bcrypt-хеш в `/var/lib/preferans-signaling/admin-auth.json`; права файла — 600. Перезапуск сохраняет пароль. После смены пароля все сеансы завершаются, требуется повторный вход.

Сеанс действует до 8 часов; выход закрывает его. Cookie — HttpOnly и SameSite=Strict; при HTTPS — Secure. Изменяющие запросы защищены CSRF-токеном. Перебор паролей ограничен. Прежний административный API `/v2/rooms` не разрешает принудительное удаление без входа через новую админку.

## Доступ из браузера

Текущий игровой сигналинг использует HTTP на порту 8080. Чтобы пароль не передавался открытым текстом через интернет, админка разрешает вход через HTTPS или локальное соединение сервера (SSH-туннель).

На компьютере в PowerShell:

```powershell
ssh -N -L 8081:127.0.0.1:8080 user@signaling.example.org
```

Оставьте команду работающей и откройте **http://127.0.0.1:8081/admin/**. Пароль при первом запуске — `admin`. Прямой вход через `http://signaling.example.org:8080/admin/` заблокирован; страница объясняет необходимость HTTPS или SSH-туннеля.

Сервер поддерживает `-tls-cert <путь>` и `-tls-key <путь>` для HTTPS. Для HTTPS адреса нужно настроить сертификат и параметры службы. Обычное обновление не меняет конфигурацию игрового сигналинга.

## Данные и действия

Страница показывает все комнаты из общего каталога VPS. В комнате видны реальные участники, их присутствие в сети, открытый стол и известные серверу партии. В списках игроков ботов нет. Для партий показываются ведущий, состав без ботов, номер раздачи, начало, окончание и идентификатор.

Данные представлены таблицей **Комната | Игроки | Партии**. У каждого элемента есть кнопка удаления с подтверждением в диалоговом окне страницы. Игроки с одинаковым именем остаются разными строками; короткий идентификатор помогает различить устройства.

Кнопка со стрелкой и названием комнаты сворачивает или разворачивает её игроков и партии. В свёрнутом виде остаются количества элементов. Состояние сохраняется при автоматическом и ручном обновлении списка в текущем сеансе.

Кнопка **Копировать** у партии помещает в буфер её сведения: комнату и идентификатор комнаты, идентификатор партии, состояние, раздачу, ведущего, игроков без ботов с идентификаторами, даты начала и окончания, дату последнего обновления. Пароли, карты и ключи подключения в текст не включаются. Если Clipboard API недоступен в браузере, используется резервный способ копирования через выделение текста внутри диалога.

- Удаление игрока отключает его от комнаты. Автоматический повторный опрос не возвращает его; явный вход в комнату разрешён. При удалении ведущего открытый стол закрывается. Сохранения и история остаются.
- Удаление партии закрывает её стол, удаляет запись каталога, а после получения уведомления устройства удаляют соответствующее локальное сохранение и историю.
- Удаление комнаты отключает её участников и удаляет все её партии и историю на устройствах после синхронизации. Для выключенных устройств удаление применяется при следующем обращении к серверу.

Сервер сохраняет отметки удаления, поэтому старое сохранение не вернёт удалённую партию в каталог после повторной синхронизации или перезапуска сервера. Для удаления требуется обновлённый сигналинг-сервер; на прежней версии кнопки отключены.

Приложения раз в `partyCatalogIntervalMs` из `config/interface.json` передают краткие сведения о локальных сохранениях всех комнат. Веб-админка читает каталог с сервера и не синхронизирует сохранения устройств сама. Данные одной партии с нескольких устройств объединяются по идентификатору партии; старые версии не заменяют новые. На сервер не передаются карты, приватные ключи или содержимое сохранения. Каталог сохраняется в том же хранилище комнат сигналинг-сервера.

Список обновляется раз в `adminRefreshIntervalMs`, пока страница открыта. Есть кнопка **Обновить**.

Для появления старых партий достаточно один раз запустить обновлённое приложение на устройстве, где они сохранены. Сведения о ещё не синхронизированных сохранениях выключенных устройств недоступны. Каталог сведений сохраняется и после отключения устройства. Полные сохранения остаются локальными; эта страница не загружает и не продолжает чужие партии.

## Обновление сигналинг-сервера

Из корня проекта, в PowerShell:

```powershell
pwsh -NoProfile -File scripts/Update-Signaling.ps1
```

Это только сборка Linux x86-64: `dist/preferans-signaling`.

Для сборки и установки на VPS:

```powershell
pwsh -NoProfile -File scripts/Update-Signaling.ps1 -Deploy
```

Адрес SSH задаётся параметром -Server или deployment.server в project.local.json. Пути по умолчанию: `/usr/local/bin/preferans-signaling`, служба `preferans-signaling`. Можно переопределить параметрами `-Server`, `-RemoteBinary`, `-Service`. Понадобятся OpenSSH (`ssh`, `scp`), доступ к VPS и `sudo`. Пароли не записаны в скрипте.

Скрипт сохраняет старый бинарник как `preferans-signaling.previous`, устанавливает новый и перезапускает службу. При ошибке перезапуска восстанавливает предыдущий бинарник. Конфигурация службы, TURN и хранилище комнат не изменяются. Перезапуск на короткое время прерывает опрос сигналинга.

## Хранение данных сигналинг-сервера

Пути ниже соответствуют рекомендуемым параметрам собственной службы; проверьте её фактический ExecStart.

Каталог комнат хранится в **одном JSON-файле, без базы данных**:

```text
/var/lib/preferans-signaling/rooms.json
```

Служба запускается командой:

```text
/usr/local/bin/preferans-signaling -data /var/lib/preferans-signaling
```

В файле сохраняются:

- комнаты: идентификаторы и названия;
- участники: имена, идентификаторы устройств, места;
- открытые столы: ведущий, состав, признаки ботов и хеши ключей повторного подключения;
- сведения о партиях: состав, состояние, раздача, даты и номер версии данных;
- отметки удаления, чтобы удалённые элементы не возвращались при синхронизации.

Файл содержит данные и контрольную сумму SHA-256. При изменении каталог записывается через временный файл и замену основного файла. Это защита от повреждения при записи, **не шифрование**.

**Только в памяти** находятся временные сообщения установления соединений. После перезапуска они исчезают, а участники считаются отключёнными до следующего обращения.

Полные сохранения партий, расклады карт и результаты розыгрышей остаются на устройствах игроков. Голос сервер не записывает.

Для резервной копии каталога достаточно сохранить `rooms.json`.

Для отдельной веб-админки добавлен файл `/var/lib/preferans-signaling/admin-auth.json`. Он содержит bcrypt-хеш пароля и признак первоначального пароля, права файла — 600. Пароль в открытом виде не хранится. Для полной резервной копии сохраните оба файла: `rooms.json` и `admin-auth.json`.

Сеансы входа в админку и ограничения попыток входа находятся только в памяти. Перезапуск сервера завершает все сеансы, но не сбрасывает пароль.
