# Публикация версий

Подробный актуальный порядок — в [`WORKFLOW-MANUAL.md`](WORKFLOW-MANUAL.md).
Здесь оставлена краткая справка по издательским скриптам.

## Приватный Release с приложениями

Используйте `scripts/Publish-Release.ps1`. Скрипт требует PowerShell 7, GitHub CLI
с выполненным `gh auth login`, локальный коммит с аннотированным тегом, а также
настроенные Go, Zig и Android SDK/NDK. Он проверяет тег, чистоту исходников сборки,
приватность репозитория и отсутствие уже существующего релиза. Сначала запустите
проверку без сборки и публикации:

~~~powershell
pwsh ./scripts/Publish-Release.ps1 -Repository <владелец>/<приватный-репозиторий> -Tag v1.0.4 -CheckOnly
~~~

Затем соберите и опубликуйте приложения:

~~~powershell
pwsh ./scripts/Publish-Release.ps1 -Repository <владелец>/<приватный-репозиторий> -Tag v1.0.4 -Notes "Описание выпуска"
~~~

Флаг ИИ по умолчанию `Off`. При необходимости его можно задать явно через `-AI`.
Версия Android берётся из тега, `versionCode` автоматически увеличивается.
Готовые вложения: `Preferans.exe`, `Preferans.apk`, `version.json`, лицензии и
`SHA256SUMS.txt`. Существующий релиз скрипт не перезаписывает.

## Публичные исходники

Публичный `gchet/Preferans` намеренно ведётся из очищенного снимка и имеет свою
историю. Не отправляйте туда локальные коммиты или теги из основной рабочей копии.
Для обновления подготовьте снимок командой `scripts/Prepare-PublicSnapshot.ps1`,
проверьте его Gitleaks, затем перенесите в отдельный клон публичного `main` и
создайте публичный коммит и тег на основе его истории. Полные команды и безопасная
замена файлов в отдельном клоне приведены в [`WORKFLOW-MANUAL.md`](WORKFLOW-MANUAL.md).

Публичный тег версии и одноимённый локальный тег могут указывать на разные коммиты:
содержимое версии совпадает, а локальная история не попадает в публичный репозиторий.
Не используйте `Publish-PublicRelease.ps1` для такого обновления снимка: этот
скрипт требует, чтобы публичный тег указывал на тот же коммит, что локальный.

## Полезные ограничения

- `-CheckOnly` только проверяет готовность; он не запускает сборку и не создаёт Release.
- `-Notes` задаёт описание релиза; многострочные заметки можно передать через `-NotesFile`.
- `-Draft` оставляет приватный Release черновиком.
- `-VersionCode`, `-AndroidSdk`, `-Zig` и `-Gradle` при необходимости переопределяют значения сборки.
- Публикуемый APK использует текущую debug-подпись. Ключ подписи храните отдельно от Git.
- При сбое загрузки проверьте черновик и файлы в `.build/releases/<тег>` перед повторной публикацией.

## Сборка релиза на GitHub Actions

Workflow `.github/workflows/release.yml` собирает приложения на GitHub и создаёт
**черновик** Release (публикуйте его вручную после проверки). Запуск — тегом версии
(`git push origin v2.0.0`) либо вручную: Actions → Release build → Run workflow,
указав существующий тег.

- Windows: `Preferans.exe` собирается на `ubuntu-latest` кросс-компилятором MinGW-w64
  (потоки POSIX, статическая линковка, без лишних DLL; без встроенного ИИ — тег `noai`).
  Шаг проверяет подсистему Windows GUI и отсутствие зависимостей от `libstdc++`,
  `libgcc` и `libwinpthread`.
- Android: `Preferans.apk` (ARM64, `versionCode` — время коммита тега) и `version.json`.
- Во вложения Release добавляются `LICENSE`, `THIRD_PARTY_NOTICES.md`,
  `third-party-licenses.zip` и `SHA256SUMS.txt`; описание берётся из аннотации тега.
- Сборка публичная: `config/local/build.json` пустой, личные адреса в неё не попадают.
- Подпись APK: чтобы приложение обновлялось поверх установленного, положите base64
  постоянного ключа (например, `~/.android/debug.keystore`) в секрет репозитория
  `DEBUG_KEYSTORE_B64`. Без секрета workflow выдаёт предупреждение, а APK подписывается
  одноразовым ключом.
- Номер версии лежит в файле `VERSION` (сейчас 2.0.1): `build.ps1` берёт его, если не задан `-VersionName`,
  а workflow проверяет, что тег (`vX.Y.Z`) совпадает с ним.
- Локально MinGW-w64 подключается параметром `-Mingw <каталог bin>` скрипта `build.ps1` (или `tools.mingw` в `project.local.json`).
