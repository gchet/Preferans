# Публикация версий
Скрипты используют GitHub CLI (gh auth login), PowerShell 7 и обычную сборку.
Перед публикацией исходники должны быть закоммичены, HEAD должен совпадать
с тегом версии. Существующий релиз скрипты не перезаписывают.

## Приватные бинарные релизы
Существующий scripts/Publish-Release.ps1 сохраняет прежнюю схему:
приватный репозиторий содержит только README и готовые вложения.
Исходники и их история туда не передаются. Доступ — по приглашению в Settings /
Collaborators репозитория. Адрес по умолчанию сохранён для прежней публикации;
другой задаётся через -Repository OWNER/REPO.
~~~powershell
pwsh ./scripts/Publish-Release.ps1 -Tag v1.0.0 -CheckOnly
pwsh ./scripts/Publish-Release.ps1 -Tag v1.0.0 -Notes "Описание выпуска"
~~~

## Публичный репозиторий исходников
Используйте отдельный новый репозиторий из проверенного чистого снимка.
Снимок готовит scripts/Prepare-PublicSnapshot.ps1:
~~~powershell
pwsh ./scripts/Prepare-PublicSnapshot.ps1 -CheckOnly
pwsh ./scripts/Prepare-PublicSnapshot.ps1 -Destination .build/public-source
~~~
Команда копирует текущие исходники, включая новые файлы, исключает удалённые,
игнорируемые файлы и Git-историю. Она не создаёт коммит и не публикует репозиторий.
Перед git init выполните проверку секретов в снимке (например, gitleaks dir --redact).
Исходная локальная история остаётся без изменений.

Не переносите старую локальную Git-историю с личными данными и не отправляйте
её в новый remote. Создание репозитория/первого коммита выполняется отдельно,
после проверки снимка.

В новом публичном репозитории сначала отправьте коммит и соответствующий тег.
~~~powershell
pwsh ./scripts/Publish-PublicRelease.ps1 -Repository OWNER/REPO -Tag v1.0.0 -CheckOnly
pwsh ./scripts/Publish-PublicRelease.ps1 -Repository OWNER/REPO -Tag v1.0.0 -NotesFile release-notes.md -Draft
~~~
Скрипт проверяет публичность репозитория и соответствие опубликованного тега
локальному коммиту. Затем собирает с -Public, исключающим личные серверные
значения даже при наличии project.local.json. Локальные пути инструментов
используются только при сборке. Этот скрипт сам не выполняет git push.

## Параметры и результат
- -Notes — описание релиза; -NotesFile — многострочное описание из UTF-8 файла.
  Вместе эти параметры не используются.
- -CheckOnly проверяет готовность без сборки и публикации.
- -Draft оставляет черновик; иначе после проверки вложений он публикуется.
- -AI по умолчанию Off для обоих издателей; локальная build.ps1 по умолчанию On.
- -AndroidSdk, -Zig, -Gradle передаются сборке.
- -VersionCode должен возрастать; по умолчанию выбирается автоматически.

Вложения: Preferans.exe, Preferans.apk, version.json, LICENSE,
THIRD_PARTY_NOTICES.md, third-party-licenses.zip и SHA256SUMS.txt.
Имена EXE/APK для игроков сохранены. Сервер, логи, эмулятор и служебные сборки
не загружаются. Архивы Source code в публичном репозитории содержат исходники;
в старом приватном — только README.

При сбое загрузки остаётся черновик; готовые файлы находятся в
.build/releases/ТЕГ. Скрипт проверяет фактический флаг ИИ и хеш EXE, имена/размеры
вложений. Публикация новой версии не изменяет уже установленные приложения.

APK сохраняет текущую debug-подпись. Резервную копию ключа храните отдельно
от Git: другой ключ не позволит установить обновление поверх старой версии.
Обновление Android через локальный Windows сервер по Wi-Fi продолжает работать.
