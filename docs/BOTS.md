# Боты

## Локальный бот с поиском

Вариант «Локальный бот» не требует API, ключей или доступа к интернету.
Решения принимает устройство ведущего. Облачные модели остаются отдельным выбором.

## Розыгрыш

Бот получает только отфильтрованный снимок: собственную руку, действительно открытые
руки, управляемую руку защитника, публичный прикуп, известный ему снос, завершённые
взятки и доказанное отсутствие мастей. Полные закрытые руки из состояния партии
в алгоритм поиска не передаются.

По этим данным формируются допустимые распределения неизвестных карт между
руками, неизвестным сносом и ещё закрытой картой прикупа на распасах.
Известные ограничения не ослабляются. Счётчик допустимых продолжений распределения
задаёт веса ветвей: все совместимые с фактами расклады имеют равную вероятность.
Это условная равномерная модель раздачи. Вероятностные предпочтения, полученные
из торговли или стратегии предыдущих ходов, пока не используются.

Каждый допустимый ход проверяется на одних и тех же случайных раскладах.
Продолжение моделируется до конца раздачи с тактическими эвристиками; когда осталось
не больше заданного числа карт, выполняется полный перебор продолжений.
Оценку даёт настоящий расчёт приложения с выбранными соглашениями, включая
вистование, ответственность, мизер, распасы и записи сдающему.
На обычной игре защитники при поиске сотрудничают против играющего; на распасах
каждый стремится улучшить собственный результат.

Это поиск Монте-Карло по возможным раскладам с точным перебором окончания,
а не перенос Python-кода и не реализация дерева ISMCTS.
Точный перебор относится к конкретному смоделированному раскладу; он не означает,
что бот знает настоящие закрытые карты.

## Остальные решения

Торговля и снос используют локальные эвристики защищённых старших карт, длинных
козырей, коротких боковых мастей и опасных разрывов в руке на мизере.
При сносе перебираются пары карт и допустимые контракты.
Обычный мизер всегда берёт прикуп. Если разрешены отдельные заявки без прикупа,
торговля идёт в порядке: мизер → девятерные → мизер без прикупа → 9 без
прикупа → десятерные. Заявки без прикупа появляются только после обычного
мизера: мизер без прикупа доступен первоначальному мизерующему, единая
девятерная без прикупа — остальным. Её победитель отдельно выбирает масть
или БК, не ниже своей ранее объявленной девятерной; снос не выполняется. Отказ от прикупа относится к заявке noTalon, а не ко
всем мизерам в партии. Дополнительные заявки включаются отдельным правилом.
Бот в обычном вистовании пасует. На первой защитной руке после отказа второго
защитника (Пас или Свои) он перевистовывает, когда это разрешено движком.
Отладочное принуждение к распасам/мизеру сохранено.

## Ответы на предложения

Локальный бот отвечает на «Предложить» с помощью ограниченного по времени
точного поиска по видимым рукам. Для обычной игры он принимает, если играющий
может гарантировать предложенные взятки, либо уступает защите больше взяток.
Для мизера принимается вариант, при котором защита не может заставить играющего
взять больше предложенного; добровольно уступленные защите взятки также выгодны.
Учитываются карты незавершённой взятки, козырь и необходимость отвечать двумя
защитниками на мизере и проверяемой десятерной. Скрытые руки не используются.
При неполной информации или истечении времени без доказательства бот отказывается.
Проверка выполняется отдельно от интерфейса; её результат записывается в журнал.

## Параметры

В config/interface.json:

- localBotSearchTimeMs: 1200 — максимальное время поиска одного хода.
- localBotSearchSamples: 120 — максимальное число полностью проверенных раскладов.
- localBotExactCards: 15 — порог полного перебора, суммарно по игровым рукам.

После изменения ресурса нужно пересобрать приложение.
Поиск выполняется в фоне и отображается существующим индикатором «думает».
При паузе, выходе или изменении состояния устаревшее решение не применяется.
При исчерпании времени используется лучший результат завершённых выборок;
если таких выборок нет, применяется допустимый эвристический ход.
В журнале записываются число раскладов, число узлов и время поиска.

## Проверки

Тесты сопоставляют симулятор с игровым движком для трёх и четырёх участников,
обычных контрактов, мизера и распасов. Проверены точность итоговых записей,
сохранение открытых рук, запреты отсутствующих мастей, независимость от настоящих
закрытых рук, условные вероятности выборки, отмена решения при паузе и окончание,
в котором поиск сохраняет контракт, а прежний выбор младшей карты его срывал.
Общая сила бота требует дальнейшего сравнения на наборах одинаковых раздач.

localBotExactCardsLimit: 15 ограничивает разрешённый порог полного перебора.

## ИИ-боты

Реализовано для Windows и Android. Модель выбирает действия, а Go-движок проверяет их и применяет. Все запросы выполняются на устройстве ведущего. Остальным участникам передаются только обычные игровые обновления и имена ботов с алиасами.

## Настройка

1. Откройте **Настройки → ИИ боты**.
2. В разделе **API-ключи** задайте название и значение ключа и нажмите **Сохранить ключ**. Одному ключу можно назначить несколько моделей.
3. Нажмите **Добавить**. Задайте уникальный алиас, провайдера, полный HTTPS адрес API, идентификатор модели, ключ, MaxTokens и температуру.
4. Нажмите общую кнопку **Сохранить**.
5. На игровом столе до начала партии нажмите значок робота рядом с именем нужного бота и выберите модель. Во время партии этот выбор доступен в ручной паузе.

Адрес для Groq: `https://api.groq.com/openai/v1/chat/completions`. Идентификатор модели берите из своего кабинета провайдера. Поддерживается формат OpenAI-compatible Chat Completions, JSON Object Mode, `max_tokens` и `temperature`. Нативные форматы других API требуют отдельного адаптера.

Поле **Провайдер** — название для пользователя; запрос отправляется по заданному URL. Количество моделей отдельно не ограничивается. Алиасы сравниваются без учёта регистра после удаления крайних пробелов. Начальные параметры новой модели: MaxTokens 500, температура 0. Для reasoning-моделей может потребоваться больший MaxTokens. Провайдер может ограничивать значения параметров; серверные ошибки видны в журнале, параметры не меняются автоматически.

Общий таймаут по умолчанию — **10 секунд**, диапазон 1–120 секунд. Он включает генерацию вариантов действий, все запросы, ожидание ограничений API и исправляющий запрос. Если времени не хватило, ход делает локальный бот. Действия с единственным допустимым вариантом выполняются без вызова модели.

## Поведение

- Поддерживаются торговля и «Здесь», снос, заказ контракта, специальные действия, вист/пас/свои, выбор открытой или закрытой защиты, ловля мизера, розыгрыш, предложения взяток и ответы на них.
- При сносе модель сначала выбирает пару карт, затем контракт; оба выбора входят в общий таймаут. В режиме «Прикуп в морду» снос остаётся заданным правилами.
- Для фаз используются отдельные инструкции. Правила стола передаются при каждом запросе вместе с собственной рукой, доступными открытыми руками, историей торговли и завершённых взяток, текущей взяткой и выведенными кодом отсутствующими мастями.
- Закрытые руки и неизвестный снос модели не передаются. Защитник мизера видит набор из 12 карт только в том объёме, в котором он доступен человеку по правилам приложения.
- Ответ — JSON с нулевым индексом `move` и необязательным коротким `why`. Проверяются формат, диапазон и допустимость команды движком. Неверный ответ исправляется не более одного раза. Для 429/503 допускается ограниченный повтор с учётом Retry-After; всего не более трёх запросов на один выбор.
- Пауза, изменение состояния, смена модели, выход из партии или приложения отменяют текущий запрос. Ответ от старой ревизии не применяется.
- Назначение модели сохраняется с партией. При переименовании алиаса назначение сохраняется. При удалении модели используется локальный бот с предупреждением. Разовый резервный ход не меняет имя бота.
- Отладочный режим распасов/мизера задаёт торговлю локальным алгоритмом; дальнейшие решения назначенного ИИ остаются активными.

Для старой сохранённой раздачи история торговли и взяток до обновления может отсутствовать: приложение не восстанавливает её выдуманными данными. С новой раздачи история записывается полностью.

## Отладка

В настройках отдельно включаются отладка торговли и розыгрыша. Бот ожидает
ведущего перед действием в выбранной фазе. Правый клик (долгое нажатие на Android)
открывает меню: продолжить или перехватить действие. Заказ при торговле выполняется
обычным окном ставки; при сносе выбираются две показанные карты бота, затем игра.
Отладочный просмотр скрытых карт доступен ведущему и не раскрывается другим
участникам или модели. Просмотр приостанавливает партию.

## Промпты и разбор решений

Общая инструкция содержит развёрнутые правила приложения: порядок торговли, роли участников, обязательства вистующих, расчёт записей, мизер, распасы и предложения. В каждом запросе поле ruleExplanation дополнительно описывает фактически выбранные договорённости стола словами, на выбранном языке промптов. Оно формируется из текущих правил, а не из фиксированных настроек по умолчанию. Шаблоны этих пояснений находятся в разделе agreements файла config/ai-prompts.json; исходные значения по-прежнему передаются в view.rules. Правила и состояние отправляются при каждом решении, включая отдельный выбор контракта после сноса.

Промпты находятся в config/ai-prompts.json. Для каждого этапа есть независимые русская (ru) и английская (en) версии: общая инструкция, торговля, снос, заказ контракта, защита, розыгрыш, исправление ответа и обсуждение. После изменения ресурса пересоберите приложения. В **ИИ боты → Язык промптов** выбирается отправляемая версия; по умолчанию русский. Изменение русского текста не изменяет английский автоматически. Обе версии требуют писать объяснение why по-русски.

Для подробного разбора включите **Игра → Отладка**, затем **ИИ боты → Разбирать ответы ИИ перед выполнением**. После ответа действие не выполняется: окно показывает параметры модели, выбранное действие по-русски, объяснение, точные сообщения каждого запроса и исходный ответ, включая исправления и отдельный заказ контракта после сноса. Ошибочный ответ тоже можно изучить; после подтверждения выполнится показанное резервное действие локального бота. Единственный допустимый вариант выполняется без запроса и без окна разбора.

Партия и её время приостановлены для всех. Кнопка **Продолжить** применяет выбранное действие ровно один раз. Если окно закрыто, его можно открыть значком ожидающего бота. Разбор предназначен ведущему; запросы, скрытые карты и ответы другим участникам не передаются. Ожидание подтверждения не ограничено таймаутом API. При изменении партии или настроек неподтверждённое решение отменяется. После перезапуска приложения незавершённый разбор не восстанавливается, бот принимает новое решение.

В окне есть **Вопрос о решении → Спросить модель**. Обсуждение получает исходные запросы и ответы и историю вопросов этого решения, без новых закрытых рук. Модель объясняет причины, предположения и альтернативы по-русски; это не доступ к скрытой внутренней цепочке рассуждений. Обсуждение не меняет решение и не выполняет игровые команды. История обсуждения ограничена 20 репликами; длина вопроса — до 2000 символов; применяется общий таймаут и параметры модели. При ошибке вопрос можно повторить.

## Хранение ключей

В каталоге данных приложения:

- `ai-settings.json` — модели, ссылки на ключи, названия ключей и таймаут.
- `ai-keys.json` — зашифрованные значения ключей.
- Назначения ботов — в локальных сохранениях партии, без ключей.

Windows использует DPAPI текущего пользователя; Android — AES-256-GCM с ключом в Android Keystore. Простое копирование файла ключей между устройствами не работает. APK не содержит пользовательских ключей. Обычное обновление поверх приложения сохраняет локальные настройки и ключи; удаление приложения Android уничтожает его хранилище.

При редактировании ключа поле значения пустое. Введите новое значение для замены; пустое поле оставляет существующий ключ. Значок глаза показывает или скрывает только введённое значение. Ключ, используемый сохранённой моделью, удалить нельзя: сначала измените назначение и сохраните настройки.

## Перенос с компьютера на планшет

1. Обновите оба приложения до версии с поддержкой ИИ. Запустите Windows-приложение; существующий сервер обновлений обычно работает на порту 8787.
2. На компьютере в **ИИ боты → Перенос настроек ИИ по Wi-Fi** нажмите **Создать код переноса**. Модели перед этим сохраняются.
3. На планшете в том же разделе укажите адрес компьютера, например `http://192.168.1.10:8787`, и полученный код. Адрес из настройки обновлений подставляется автоматически.
4. Нажмите **Получить настройки ИИ** и подтвердите замену местного списка моделей и ключей.

Код состоит из **6 десятичных цифр**, включая возможные нули в начале. Код разрешает одноразовую передачу; шифрование использует отдельные случайные ключи и обмен X25519, а не короткий код. Пакет зашифрован AES-GCM. Код действителен **5 минут**, пакет отдаётся один раз. После 10 неверных попыток код отменяется. На планшете ключи заново шифруются через Android Keystore. При неудачном получении создайте новый код. Каждому дополнительному планшету нужен новый код; сами API-ключи повторно вводить не нужно. Перенос не включён в APK автоматически, чтобы готовое приложение не распространяло ваши секреты.

## Журнал и проверки

В экранном журнале: начало решения, модель, действие, время, токены, число запросов и причина резервного хода. HTTP тела ошибок и заголовки авторизации не выводятся.

Если включён файл журнала, туда дополнительно пишется JSON доступной боту ситуации, вариантов действий и краткого объяснения. Это локальные диагностические сведения о картах бота; они не рассылаются другим участникам. Значение API-ключа в этот журнал не записывается.

Проверены локальные сценарии с тестовым HTTPS API, неверным JSON, неверным индексом, ограничениями запросов, таймаутом, паузой, сохранением назначений, шифрованием DPAPI и одноразовым переносом. Android Keystore включён в успешно собираемую APK. Сила игры реальной модели и реальные задержки требуют проверки с вашим API-ключом; сборка сама по себе не подтверждает улучшения бота.

Описание API: [Groq Chat Completions](https://console.groq.com/docs/api-reference). Защита ключей: [Windows DPAPI](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata), [Android Keystore](https://developer.android.com/privacy-and-security/keystore).
