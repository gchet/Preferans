# Архитектура

## Компоненты
| Каталог | Роль |
|---|---|
| web/src | Общий HTML/TypeScript/CSS интерфейс |
| internal/game | Правила, состояния и расчёт записей |
| internal/app | RPC, ведущий/участник, боты, сохранения, пауза и восстановление |
| internal/network | WebRTC, ICE, STUN/TURN и диагностика |
| internal/rooms | Каталог комнат, составы, сигналинг, администрирование |
| internal/storage | Локальные настройки и сохранения |
| internal/ai | Необязательные обращения к моделям |
| internal/secrets | Платформенная защита ключей |
| cmd/preferans | Windows оболочка и headless запуск для тестов |
| cmd/signaling | Отдельный сервер комнат |
| mobile | API Go для gomobile |
| android/app | Kotlin WebView, микрофон, обновления, Android Keystore |
| config | Встроенные параметры и промпты |
| locales | Общие языковые JSON-ресурсы для Go, WebUI и Android |

## Интерфейс и локальный API
Vite собирает WebUI в web/dist; Go встраивает результат в приложение.
Отдельный Vite-конфиг собирает страницу администрирования в
internal/adminweb/static для сигналинг-сервера.

В Windows Go запускает HTTP-сервер на loopback и открывает WebView2.
В Android Kotlin запускает Go через gomobile и показывает тот же URL
в Android WebView. Общие действия — HTTP POST /api с JSON action и параметрами.
Состояние получается периодическим опросом. Игровой движок исполняется в Go,
а не в браузере.

Случайный токен локального API передаётся через fragment URL и заголовок
X-Preferans-Token. API не предназначен для удалённого доступа.
Отдельный HTTP-сервер Wi-Fi обновлений обслуживает APK и манифест; доступ к нему
и firewall настраиваются отдельно.

Мост PreferansAndroid используется для платформенных функций: разрешений
микрофона, установки APK, сохранения журнала, работы с защищёнными ключами.
В Windows такие функции реализованы Go/нативной оболочкой.

## Комнаты и восстановление

Каталог комнат обслуживает отдельный Go-сервер (cmd/signaling). Он обменивается
сообщениями согласования WebRTC и хранит каталог комнат/партий; полный игровой
расклад и сохранения остаются на устройствах. Ведущий создаёт стол и является
авторитетным игровым узлом. TURN ретранслирует трафик, если прямая связь невозможна.
Роль ведущего автоматически не передаётся.

Комната вмещает до четырёх устройств. Выбранная комната сохраняется; комната
по умолчанию используется только при отсутствии выбора. Имена не являются
идентификаторами: каждое устройство имеет собственный секрет room-session.
Клон VM должен получить собственный каталог данных.

В комнате доступны голосовой чат и сбор участников. После создания стола
участники переходят на игровое поле. Голос передаётся через WebRTC; локальный
микрофон и общий динамик можно отключить, звук другого участника можно отключить
отдельно. При игре только с ботами микрофон не показывается.

Оборванное соединение восстанавливается автоматически через сигналинг и TURN.
Неподтверждённые/устаревшие действия не применяются; партия ждёт участников.
Ручная пауза синхронна для всех и останавливает время партии. Снять её может
установивший игрок. Выход участника не завершает стол ведущего.

Офлайн-режим использует локальную комнату и тот же игровой движок; сервер,
интернет и TURN для игры с ботами не требуются.

## Сохранения и данные
Локальные настройки не входят в состояние стола. Договорённости стола сохраняются
с партией и синхронизируются ведущим. Незавершённые сохранения для продолжения
показываются ведущему; история и каталог итогов доступны участникам.
Имена для итогов комнаты объединяются, идентификаторы устройств для соединения —
нет. Сервер хранит метаданные партий, а не полные расклады.
